# Optional project overlay

Use an overlay only when the active project needs specific rules beyond this skill.
Keep the real overlay in that project, outside this public skill distribution. Record
its source and date in the project overview. Follow current user authority and host
instructions; an overlay does not grant new permissions.

A generic outline:

- Project identifier and simulation-only scope.
- Current project instructions, specification, handoff, and execution log.
- Repository revision and project-owned artifact root, discovered locally.
- Robot, scene, control interfaces, pinned compatibility lane, and acceptance gates.
- Owners, bounded compute budget, authorized actions, and stop conditions.
- Evidence, media, backup, and shutdown requirements.

Example: a simulated warehouse robot may require a collision-free navigation gate
and an uninterrupted camera recording. The project owner defines and approves the
actual thresholds. This is a hypothetical example, not a tested robot or deployment.

Never copy a prior project's account authority, paths, versions, numeric thresholds,
checkpoints, or claims into another project.
